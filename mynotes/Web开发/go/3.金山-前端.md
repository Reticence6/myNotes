  - 事件循环（JS的执行机制/Event Loop）

    - JS 单线程 
      - JS 代码的执行分为同步代码和异步代码 
      - 当碰到同步代码的时候，直接在执行栈中执行
      - 当碰到异步代码并且时机成熟的时候（例如定时器时间到了），就会把异步代码添加到任务队列中 
      - 当执行栈中的同步代码中的同步代码执行完毕后，就会去任务队列中把异步代码取出放到执行栈中执行，这种反复去任务队列中取异步代码放到执行栈中执行的操作就是事件循环，就是 Event Loop。
      - （setTimeout不能确保按时输出，可以使用web worker确保准时，**Web Worker 是独立线程**不和主线程抢资源**主线程再卡，它也不受影响**）

  - 异步处理

    - 回调函数

      ```js
      const sum = (a, b, callback) => {
        setTimeout(function() {
          callback(a + b)  // 把结果传给回调
        }, 1000)
      }
      
      sum(1, 2, (result) => {
        console.log(result)  // 1秒后输出 3
      })
      ```

    - 使用Promise，解决了回调地狱的问题，但并不能简化代码

      ```js
      const sum = (a, b) => {
        return new Promise((resolve) => {
          setTimeout(() => {
            resolve(a + b) // 用 resolve 把结果交给 Promise
          }, 1000)
        })
      }
      
      // 链式调用，代码平铺，没有嵌套
      sum(1, 2)
        .then(r => sum(r, 1)) // 3
        .then(r => sum(r, 1)) // 4
        .then(console.log)    // 最终输出 4
      ```

    - 使用async/await，将异步代码写成同步风格

      ```js
      const sum = (a, b) => {
        return new Promise((resolve) => {
          setTimeout(() => {
            resolve(a + b)
          }, 1000)
        })
      }
      
      // 用 async 函数包裹，await 等待 Promise 完成
      async function calc() {
        let r = await sum(1, 2) // 等待 1 秒，拿到 3
        r = await sum(r, 1)     // 再等 1 秒，拿到 4
        r = await sum(r, 1)     // 再等 1 秒，拿到 5
        console.log(r)          // 输出 5
      }
      
      calc()
      ```

## Hooks

useEffect：处理副作用，一般在useEffect中发送请求

- 副作用回调函数，return-清理函数，依赖项
- 副作用回调函数执行时机：
  - 依赖项不写，初始化以及任何状态变，副作用回调函数都会走
  - 依赖性为空数组，初始化时走
  - 依赖项为 [name, count]，初始化走，只有name和count依赖项变化的时候会走
- 清理函数
  - 用于组件销毁时解绑事件；清理定时器
  - 组件销毁时会走
  - 下一次副作用回调函数执行时会走

useRef：操作DOM，实现共享数据，多次渲染仍共享的是同一个数据

useCallback：

- React.memo包裹Child组件，参数变化时才重新渲染；但是父组件传函数时，改变父组件，子组件还是会重新渲染（父组件重新渲染，重新声明了函数，每次传的都是一个新的函数）
- 使用useCallback包裹这个函数，行成一个唯一的函数引用
